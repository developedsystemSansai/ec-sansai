# EC Online Submission — ระบบยื่นขอรับการพิจารณาจริยธรรมการวิจัยในมนุษย์
โรงพยาบาลสันทราย. กลุ่มงานพัฒนาคุณภาพและระบบบริการ.

ระบบนี้ให้ผู้วิจัยยื่นโครงการออนไลน์. เจ้าหน้าที่ตรวจ. กรรมการประเมิน. ประชุม. แจ้งผล. ติดตามหลังรับรอง. ทั้งหมดอยู่ที่เดียว.

## ภาพรวม (ระบบมี 3 ก้อน)

```
 คน (เบราว์เซอร์)
      │
      ▼
 [ ก้อน 1: หน้าเว็บ ]  HTML ล้วน อยู่บน GitHub Pages
      │   POST (JSON) ไปที่ GAS_URL ใน config.js
      ▼
 [ ก้อน 2: Backend ]   Google Apps Script (code.gs) — doPost router 88 action
      │
      ├─► Google Sheets  เก็บข้อมูล 10 แท็บ
      ├─► Google Drive   เก็บไฟล์ (โฟลเดอร์ EC_Uploads)
      ├─► Gmail (MailApp) ส่งอีเมลแจ้งเตือน
      └─► LINE API       แจ้งกรรมการ (webhook + push)
```

ไม่มีเซิร์ฟเวอร์ของเรา. ไม่มีฐานข้อมูลแยก. หน้าเว็บคุยกับ GAS ตัวเดียว.

## ก้อน 1 — หน้าเว็บ (`ec-sansai-main/`)

**หน้าสาธารณะ** (ไม่ต้องล็อกอิน)

| ไฟล์ | หน้าที่ |
|---|---|
| `index.html` | หน้าแรก. ทางลัด. สถิติ. ปฏิทินประชุม. ข่าว. ป๊อปอัปคู่มือ. |
| `process.html` | 5 ขั้นตอนการยื่น |
| `documents.html` | แบบฟอร์ม IS.01–IS.09 (บังคับ 9 + เพิ่มเติม 9) |
| `tracking.html` | ตรวจสถานะโครงการด้วยอีเมล + สถิติรวม |
| `standards.html` | มาตรฐานการวิจัย (ICH-GCP, SOP, คำสั่ง) |
| `training.html` | หลักสูตรอบรมจริยธรรมการวิจัย |
| `contact.html` | ติดต่อ. เวลาให้บริการ. LINE. |
| `privacy-policy.html` | นโยบาย PDPA |
| `reset-password.html` | ตั้งรหัสผ่านใหม่ (ลิงก์จากอีเมล) |

**แอป** — `app.html` ไฟล์เดียว. ล็อกอินแล้วเห็นเมนูตามบทบาท.

| หน้าในแอป | ใคร |
|---|---|
| หน้าหลัก / ข้อมูลส่วนตัว | ทุกคน |
| ยื่นโครงการใหม่ / โครงการของฉัน | ผู้วิจัย |
| ต้องตอบรับ | กรรมการ, เจ้าหน้าที่, ผู้ดูแล |
| ต้องประเมิน | กรรมการ, ผู้ดูแล |
| การประชุม | กรรมการ, เจ้าหน้าที่, ผู้ดูแล |
| จัดการโครงการ | เจ้าหน้าที่, ผู้ดูแล |
| ประวัติงานวิจัย | ตามสิทธิ์ |
| ดาวน์โหลดแบบฟอร์ม | ผู้วิจัย, เจ้าหน้าที่, ผู้ดูแล |
| รายงานการประชุม | กรรมการ, ผู้ดูแล |

คนหนึ่งมีได้หลายบทบาท. หลังล็อกอิน ระบบพาไปหน้าแรกของบทบาท: ผู้ดูแล/เจ้าหน้าที่ → จัดการโครงการ. กรรมการ → ต้องตอบรับ. ผู้วิจัย → โครงการของฉัน.

## บทบาท 4 แบบ

| บทบาท | ทำอะไร |
|---|---|
| `researcher` ผู้วิจัย | สมัคร. ยื่นโครงการ. แนบไฟล์. ส่งแก้ไข. ส่งรายงานผลวิจัย. |
| `staff` เจ้าหน้าที่ | ตรวจเอกสาร. กำหนดประเภท. มอบหมายกรรมการ. ดูภาพรวม. |
| `committee` กรรมการ | ตอบรับงาน. ประเมิน. ลงความเห็นในประชุม. |
| `admin` ผู้ดูแล | ทำได้ทุกอย่าง. อนุมัติผู้ใช้. ปลดล็อกบัญชี. จัดการประชุมและรายงาน. |

## เส้นทางของโครงการ (จากโค้ด)

1. **สมัครและรออนุมัติ** — ผู้ดูแลอนุมัติบัญชี (ใช้เวลา 1–2 วันทำการ).
2. **ยื่น** — กรอกข้อมูล. แนบเอกสาร. ยื่นก่อนประชุมอย่างน้อย 15 วันทำการ.
3. **ตรวจเอกสาร** — เจ้าหน้าที่ตรวจ. ครบ → `ผ่านตรวจเอกสาร`. ไม่ครบ → ส่งกลับแก้.
4. **กำหนดประเภท** — Exempt / Expedited / Full Board.
5. **มอบหมายกรรมการ** — กรรมการ `ตอบรับ` แล้ว `ประเมิน`. Full Board เข้าประชุม.
6. **ผลพิจารณา** — `รับรอง` / `รับรองมีข้อแก้ไข` / `ไม่รับรอง`. เจ้าหน้าที่ส่งผลให้ผู้วิจัย.
7. **แก้ไขตามผล** — ผู้วิจัยส่งแก้ (นับครั้ง). แอดมินตรวจ. ย้อนสถานะได้ถ้าพลาด.
8. **หลังรับรอง** — ส่งรายงานผลวิจัย. ใกล้หมดอายุ ระบบเตือน. จบ → ปิดโครงการ.

อายุการรับรองเริ่มต้น 12 เดือน. ปรับได้ด้วย `EC_VALIDITY_MONTHS`.

## ก้อน 2 — Backend (`backend/code.gs`)

- ทางเข้าเดียว: `doPost(e)`. ส่ง `action` มา. router เลือกงาน. มี 88 action.
- กลุ่ม action: บัญชี/เซสชัน, โครงการ, ไฟล์, กรรมการ/ประเมิน, ประชุม, รายงานวิจัย, แจ้งเตือน, สถิติสาธารณะ, PDPA, LINE.
- มี action สาธารณะ (ไม่ต้องล็อกอิน) สำหรับหน้าแรกและ `tracking.html`: `getPublicMeetings`, `getPublicProjectStats`, `getProjectTrackingByEmail` ฯลฯ.

**ข้อมูล (Google Sheets 10 แท็บ)**
`Users` `Sessions` `Projects` `ProjectAssignments` `ProjectResults` `Meetings` `MeetingMinutes` `ResearchReports` `PdpaConsents` `AuditLog`

**ไฟล์** — Drive โฟลเดอร์ตาม `DRIVE_FOLDER_ID`.

**งานตั้งเวลา (trigger 4 ตัวในโค้ด)**
`checkExpiringProjectsAndNotify` (เตือนใกล้หมดอายุ) · `cleanExpiredSessions` · `runDataRetention` · `dailySecurityCheck_`

## ตั้งค่า

**Script Properties** (Apps Script → Project Settings)

| ชื่อ | ต้องมี | ใช้ทำอะไร |
|---|---|---|
| `SHEET_ID` | ใช่ | ไอดี Google Sheet |
| `DRIVE_FOLDER_ID` | ใช่ | โฟลเดอร์เก็บไฟล์ |
| `GITHUB_ORIGIN` | ใช่ | โดเมนหน้าเว็บ. ไม่ตั้ง = ทุก request ถูกปฏิเสธ. |
| `EC_VALIDITY_MONTHS` | ไม่ | อายุรับรอง (ค่าเริ่มต้น 12) |

**หน้าเว็บ** — `ec-sansai-main/config.js` มีแค่ `GAS_URL` (ลิงก์ Web App ที่ deploy แล้ว).
ใน `code.gs` มี `CUSTOM_DOMAIN` เขียนตายตัว ชี้ GitHub Pages. ย้ายโดเมนต้องแก้ตรงนั้นด้วย.

## Deploy

1. **Backend** — วาง `backend/code.gs` ใน Apps Script. ตั้ง Properties 3 ตัวบน. Deploy เป็น Web app. คัดลอก URL.
2. **หน้าเว็บ** — ใส่ URL ใน `ec-sansai-main/config.js`. Push โฟลเดอร์ขึ้น GitHub Pages.
3. **ตั้ง `GITHUB_ORIGIN`** ให้ตรงโดเมนหน้าเว็บ.
4. ล็อกอินทดสอบ. ลองยื่นโครงการ. ลองอัปโหลดไฟล์.

ผมไม่ได้เห็นฟังก์ชันตั้ง trigger ตอนติดตั้งครั้งแรกอย่างชัดเจน. ถ้าอีเมลเตือนไม่มา ให้เช็กหน้า Triggers ใน Apps Script.
